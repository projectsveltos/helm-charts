# Third-Party License Notices

Sveltos is composed of several container images deployed together by this Helm chart:
`access-manager`, `addon-controller` (built from the closed-source `sveltos-enterprise`
repository, which statically links the open-source `addon-controller` code plus licensed
premium features into the one image everybody pulls), `classifier`,
`clusterinventory-controller`, `crd-manager`, `event-manager`, `healthcheck-manager`,
`mcp-server`, `register-mgmt-cluster`, `shard-controller`, `sveltoscluster-manager`,
`techsupport`, plus `sveltos-agent`, `drift-detection-manager` and `sveltos-applier`, which
this chart's controllers deploy into managed clusters at runtime rather than listing as chart
dependencies themselves.

Regardless of whether a given Sveltos component's own source is open source or closed source,
every one of these images embeds a large tree of third-party open-source dependencies. This
document lists every third-party license found across that combined set, generated by scanning
each image's actual build target with
[`google/go-licenses`](https://github.com/google/go-licenses):

```
go-licenses report <build-target>
```

for each repository/target above (`sveltos-enterprise`'s target is `./cmd/enterprise-manager`,
the one that actually produces the `addon-controller` image). First-party
`github.com/projectsveltos/*` packages are excluded (they're Sveltos's own code, not
third-party). A handful of packages `go-licenses` can't auto-classify are resolved by hand; see
`MANUAL_PATCHES` in `scripts/render_licenses.py` for which ones and why.

**sveltosctl** and the **dashboard + ui-backend** bundle are distributed independently of this
chart and are covered by their own separate notices (`sveltosctl/THIRD_PARTY_LICENSES.md` and
`charts/dashboard/THIRD_PARTY_LICENSES.md`), not this document.

## A note on MPL-2.0

Some dependencies may be MPL-2.0, a weak (file-level) copyleft license: it only requires
releasing *modifications to MPL-licensed files* under MPL-2.0, not the programs that merely
import them. Check whether any appear in the table below (search "MPL-2.0") -- as long as
they're consumed unmodified as ordinary library dependencies, as they always have been so far,
no obligation is triggered beyond the attribution below.

## Regenerating this document

Run `scripts/update-third-party-licenses.sh` from the repository root before cutting a release, then
review the diff. Re-run whenever a dependency is added, removed, or upgraded across any of the
images this document covers -- don't hand-edit the tables below.
